# 命名与类型判定规则

修复过程中判定页面归属、命名时遵循的规则。**核心目的**：杜绝"同一概念被建成不同类型/不同 slug 的多个页面"。

## 页面类型判定（entity vs concept）

| 信号 | 归为 entity | 归为 concept |
|------|------------|-------------|
| 具名事物 | 具体产品/工具/人物/组织/论文（如 `adas`、`openai`、`RAG-Anything`） | — |
| 抽象概念 | — | 思想/方法/现象/框架（如 `思维链（CoT）`、`过参数化`、`上下文工程`） |
| 命名含首字母缩写 | 若指向具体实现/工具（如 `MCP` 协议工具） | 若指抽象机制（如 `RLHF` 训练范式） |
| 含"论文/报告" | entity（研究论文实体） | — |

判定**不唯一**时，遵循"**合并到已存在的页面**，而非新建"：若 `entities/` 已有该概念页，则 concept 不新建，而是更新 entity 页或交叉引用。

## slug 规范化

合并候选去重时，用归一化键比较：NFKC + 小写 + 去符号（空格/连字符/下划线/括号/点/加号）+ 去目录前缀。

| 原文件名 | 归一化键 | 说明 |
|---------|---------|------|
| `http-记录与重放` | `http记录与重放` | 连字符等价 |
| `http记录与重放` | `http记录与重放` | 无符号等价 |
| `lora低秩适配` | `lora低秩适配` | 括号变体等价 |
| `lora(低秩适配)` | `lora低秩适配` | 同上 |
| `CocDo` | `cocdo` | 大小写等价 |
| `codo` | `codo` | **拼写不同** → 需 LLM 判定是否同义 |

**保留页选取**：字节更大 / sources 更多 / 入链更多者优先。

## 统一重命名规则（slug 命名规范）

对需要重命名/新建页面的 slug，按以下规则（来自实际仓库维护沉淀）：

| # | 场景 | 规则 | 示例 |
|---|------|------|------|
| 1 | 全英文 | 单词用 `-` 连接 | `entities/query-loop` |
| 2 | 中英混杂且互为释意 | 英文主词（中文释意）括号形式 | `concepts/RLHF（基于人类反馈的强化学习）` |
| 3 | 中英混杂但为组合词（无释意关系） | 规则 2 不适用，直接连写 | `entities/A2A协议` |
| 4 | 纯英文 | 用 `-` 连接 | `entities/query-loop` |
| 5 | 模型名称/版本号 | 用 `.` 分隔版本号 | `entities/claude-opus-4.6` |

注意：
- 规则 4 与规则 1 同义（英文一律用 `-` 连接）；
- 中英混杂先判断是否存在「释意」关系（中文是英文的解释）——是则用括号（规则 2），否则按组合词直接连写（规则 3）；
- 模型版本号用 `.`（如 `claude-opus-4.6`），区别于普通英文单词间的 `-`。

## 保守原则

- 归一化后唯一命中 → 可自动合并（P0）。
- 仅核心 token 子集匹配 / 括号中英文对照 → LLM 辅助判定（P1）。
- 仅语义相近、跨类型 → 人工挑选（P2）。
- `sources/` 目录摘要页**不参与合并**（它们是资料摘要，不是知识页面）。
